# B008: Frontend never sends the access token

- **Found**: 2026-11-24, E001 (F013–F015 review)
- **Severity**: Critical (security). Depending on the backend profile, either the API has no sign-in check or every call fails.
- **Where**: `ui-personal-routine-manager/src/app/App.tsx` (`accessToken` state), `src/lib/api.ts` (`apiRequest` `token` option); backend `config/SecurityConfig.java`, `config/CurrentUserGuard.java`

## What happens

- Sign-in and the silent refresh return an `accessToken`. `App.tsx` keeps it in React state and only decodes it to get the user ID.
- `apiRequest` adds `Authorization: Bearer <token>` only when a caller passes `token`. No caller does, so no API request carries the token.
- The result depends on the backend profile:
  - **`test` / `sit` / `prod`** (JWT required): every call after sign-in returns 401 "Please sign in to continue." The app is unusable.
  - **`local` / `fast`** (auth off): the app works, but `CurrentUserGuard` only checks that the user exists. Anyone who knows a user ID can read or change that user's routines, goals, settings and chats.
- The deployed backend probably runs `local`: the CI deploy sets no profile (bug-0007), and `application-local.yml` lists `https://milosbytomm.site` as a CORS origin. If so, production has no sign-in check today.

## Reproduction

1. Start the backend with sign-in on: `SPRING_PROFILES_ACTIVE=sit ./gradlew bootRun`.
2. Start the frontend (`pnpm dev`) and sign in.
3. Any page load fails: the requests have no `Authorization` header (DevTools → Network) and return 401.

Opposite case, auth off: `curl http://localhost:8080/api/v1/users/<someone-else's-id>/goals` with no token returns their goals (200).

## Expected

- Every API request after sign-in carries `Authorization: Bearer <accessToken>`, and the token is updated on login and refresh and cleared on logout.
- The deployed backend runs a profile with sign-in on, so requests without a valid token get 401 and a user can't reach another user's data (403).

## Notes

- Fix: keep the current token in one place in `lib/api.ts` (set on login/refresh, cleared on logout) and attach it in `apiRequest`, instead of passing `token` at each call site. Add a Vitest test for the header, and a Playwright run against a backend with auth on.
- After the fix, switch the deploy to an auth-on profile (ties to bug-0007). Check that an expired access token triggers a refresh (bug-0003: the refresh token lasts 15 min).
