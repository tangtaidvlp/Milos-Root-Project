# B014: Requests fail with 401 after the access token expires

- **Found**: 2026-11-26, B008 review
- **Severity**: High with auth on (`sit`/`test`/`prod`): after 15 minutes every call fails until the page is reloaded
- **Where**: `ui-personal-routine-manager/src/lib/api.ts` (`apiRequest`), `src/features/auth/hooks/useAuthSession.ts`

## What happens
The access token lasts 15 minutes (`jwt.access.expiration`). The frontend only refreshes it on page load. `apiRequest` throws `ApiError(401)` on an expired token and nothing renews it, so the app stays "signed in" while every request fails.

## Reproduction
Run the backend with auth on and a short access token (`JWT_ACCESS_EXPIRATION=60`), sign in, wait over a minute, use the app: every call returns 401.

## Expected
On a 401 (not from `/auth/*`), refresh the access token once using the refresh cookie and retry the request. Parallel 401s share one refresh. If the refresh fails, end the session and show the sign-in page.

## Notes
Needs bug-0003 fixed too: the refresh token currently also expires after 15 minutes, so the refresh would fail anyway.
