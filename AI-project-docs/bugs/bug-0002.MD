# bug-0002: Routine endpoints don't check that the routine belongs to the caller

- **Found**: 2026-11-23, F008 (research R6)
- **Severity**: High (security: OWASP ASVS access control; constitution IV "look up every user-owned entity by (user, id); 404 when it isn't the user's")
- **Where**: `api/DefaultRoutineController`, `api/DailyRoutineController` (and the services they call)

## What happens
The endpoints take a routine id, task ids or a `userId` from the URL or body and never compare them with the signed-in user. Any signed-in user who knows (or guesses) another user's ids can read and change that user's default and daily routines and tasks.

## Reproduction
1. Sign in as user A and user B (two tokens).
2. With A's token: `GET /api/v1/default-routine/users/{B's id}` → 200 with B's routine.
3. With A's token: `PUT /api/v1/default-routine/tasks` with one of B's task ids → 200, B's task changed.

## Expected
404 for anything that isn't the caller's (same as `CurrentUserGuard` does for settings, chat and reflection).

## Notes
- F008's component tests deliberately don't assert either way, so the fix only adds tests.
- Start the fix with failing component tests in `component/DefaultRoutineComponentTest` and `component/DailyRoutineComponentTest`.
