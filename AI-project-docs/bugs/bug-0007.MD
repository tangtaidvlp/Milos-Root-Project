# bug-0007: Deployed backend profile: support endpoint exposed, and CI deploy sets no profile

- **Found**: 2026-11-23, F008 (T047 discussion)
- **Severity**: Medium (security/operability)
- **Where**: `.github/workflows/gradle-publish.yml` ("Deploy Container to EC2"), `api/CronSupportController` (`@Profile({"local","fast","test"})`)

## What happens
- The EC2 backend runs the `test` profile, so `POST /api/support/cron/spawn-daily-task` exists in the deployed app. Constitution IV: support/debug endpoints MUST NOT exist in prod.
- The CI deploy step runs `docker run … <image>` with no `SPRING_PROFILES_ACTIVE`, and the `Dockerfile` sets none. A container started that way runs the default `local` profile, where authentication is switched off. The profile on EC2 must come from somewhere else (manual env); that isn't visible in the repo.
- The automated test suite also uses a profile named `test` (test classpath only), so the name means two things.

## Expected
- The deploy step sets the intended profile explicitly.
- The deployed profile doesn't enable support endpoints.
- Consider a distinct name for the deployed environment (for example `staging`), so `test` means only the test suite.
